1 · what this module does

Every DNS lookup on the phone — from every app, the browser, the system — is sent through dnscrypt-proxy, encrypted, and answered by a resolver you choose. Your mobile carrier or Wi-Fi owner can no longer read or change your DNS.

On the way, lookups for ads, trackers and malware are blocked using public blocklists (OISD, HaGeZi) plus your own rules.

requirement
CPUarm64 only
RootSukiSU Ultra or KernelSU (WebUI built in). Magisk works too — open the WebUI with MMRL or KSU WebUI Standalone.
Android9 or newer
2 · quick start
  1. Flash the zip, reboot.
  2. Open the WebUI. The green banner should say Protected.
  3. Tap DNS Test → run the extended test. You should see Cloudflare, Quad9 or Mullvad — never your carrier or ISP.
  4. Dashboard → Update Blocklist → pick your lists under Sources → Update.
Android's own Private DNS is switched off at install, otherwise Android would send DNS around the module. Uninstalling puts back whatever you had before.
3 · how protection works
app asks for a name (port 53)
↓
iptables redirect → 127.0.0.1:5354
↓
dnscrypt-proxy: allow list → blocklist → cache
↓
encrypted (DoH / DNSCrypt) to your resolvers

No leak at boot

The redirect is installed very early in boot, before the network is up and before dnscrypt-proxy starts. Until the daemon is ready, DNS simply does not work — nothing leaves the phone unencrypted.

Leak guard

Any port-53 packet that somehow escaped the redirect and is heading off the device is dropped. The same guard exists for IPv6.

QUIC block

Browsers like Chrome can do their own DNS-over-HTTPS over QUIC (UDP/443) and skip the phone's DNS entirely. Blocking UDP/443 makes them fall back to normal HTTPS over TCP, which uses the phone's DNS — and therefore this module. Switchable in Settings.

Watchdog

A background script checks everything every 10 seconds:

  • Liveness every 30 s — a question dnscrypt-proxy answers by itself, without internet. Three missed answers in a row = hung, and it is restarted (at most 5 times in 15 minutes).
  • Resolution every 60 s — a real lookup through your resolvers. Tells "working" apart from "running, but no upstream".
  • Rules every tick — Android rebuilds its firewall on every network change or VPN start; missing rules are put back within seconds.

Failsafe

If dnscrypt-proxy cannot be started (at boot: after a 90-second grace period), the redirect is removed so the phone is not left without internet. DNS then goes out unencrypted — the banner turns red — and protection comes back by itself the moment the daemon runs again. An intentional restart never triggers the failsafe.

The health checks are real DNS queries (about 180 an hour). The dashboard subtracts them from its numbers and hides them from the lists.

5 · blocklists

Sources

Open Sources next to the Update button and tick what you want. Several lists can be combined.

groupuse
OISDSmall, Big (recommended), NSFW Small, NSFW.
HaGeZiLight → Normal → Pro → Pro++ → Ultimate (stronger, more breakage), plus Threat Intelligence mini/medium.
Add-onsPop-up ads, fake & scam, gambling, NSFW, Xiaomi / Samsung / TikTok trackers, URL shorteners. Meant to stack on one main list.
Your own listsAny https:// URL. Plain domain lists, hosts files (0.0.0.0 name) and AdBlock lists (||name^) are understood.
One main list plus add-ons is usually enough. Main lists overlap heavily — duplicates are removed, but each one still costs download time and memory.

What Update does

  1. Downloads every selected list and checks it (not an error page, not truncated).
  2. Merges them, removes duplicates, and removes subdomains already covered by a blocked parent (ad.example.com is redundant when example.com is blocked).
  3. Adds custom-blocked-names.txt on top — always, whatever is selected.
  4. Reloads dnscrypt-proxy with no downtime, and confirms it actually reloaded.

Each list shows a status: updated, cached — the download failed, its last good copy is used — or failed with no earlier copy. A list never silently disappears because one download failed.

Automatic update

Off / Daily / Weekly. The next run time is shown under Automatic Update. The check happens every ~10 minutes while the phone is awake and DNS works, so a phone that slept through the due time updates shortly after it wakes. A failed attempt waits an hour before retrying.

Custom list

Edit custom-blocked-names.txt in /sdcard/dnscrypt-proxy/ with any file manager, or use Block in the WebUI. Within a minute the blocklist is rebuilt from the cached lists — no download, and removed lines really disappear.

6 · tools — check a domain & my rules

Check a domain

Type a name and tap Check:

  • Verdict — Allowed, Blocked or Not blocked.
  • Block rule — the exact rule that matches. It may be a parent: tracker.example.com is blocked by the rule example.com.
  • From — which list the rule came from: OISD Big, HaGeZi Pro, your custom list…
  • Live answer — what dnscrypt-proxy answers right now: an IP address, NXDOMAIN, or a blocked answer (HINFO).

Allow / Block buttons appear under the result.

My rules

Allowed always wins over every blocklist — the way to fix a site or app a list breaks. Blocked by you is your custom list; it survives every update. ✕ removes a rule. Everything takes effect immediately.

If you unblock a name that a downloaded list also contains, it stays blocked — you are told which list; use Allow for those.

Rule syntax (for editing the files by hand)

rulematches
example.comexample.com and every subdomain
*.example.comthe same as above
=example.comexample.com only
ads.*every name starting with ads.
*sex*every name containing sex
ads[0-9].*.comglob pattern

Anything after # is a comment. The WebUI lists pattern rules but only removes plain names; edit patterns in the file.

7 · tools — resolvers

The servers that actually answer your encrypted queries. Default: Cloudflare, Quad9, Mullvad — none of them filter, since the blocklists do that job.

Badges

DoH / DNSCryptProtocol. Both are encrypted and authenticated.
no-log logsWhat the operator declares about logging.
no filter filtersWhether the resolver blocks things itself (ads, malware) on top of your lists.
dnssecValidates DNSSEC signatures.

These properties are decoded from each resolver's signed stamp in the official public-resolvers list — what the operator itself declares, not someone's description.

Choosing

  • Test latency measures one TCP handshake to each server — a rough measure of distance, not of DNS speed.
  • Tick the ones you want (1–8) → Apply. The new configuration is checked by dnscrypt-proxy itself before it is used, and if the daemon does not come back with it, the previous resolvers are restored automatically.
  • Add from the full list searches all 700+ public resolvers.

With several resolvers, dnscrypt-proxy spreads queries over them and prefers the fastest.

8 · system — pause protection

Hotel, airport and train Wi-Fi often show a login page first, and it only works with the network's own DNS. Until you log in, encrypted DNS cannot get through — the banner shows Nothing resolves.

Pause 5 / 15 / 60 min removes the redirect for that time so the login page can load. Resume ends it early. It always ends by itself when the time is up and after any reboot.

While paused, DNS goes out unencrypted. Log in, then Resume.

Actions

Restart daemonRestarts dnscrypt-proxy (~2 s). Protection stays up meanwhile.
Reload listsRe-reads the block and allow lists without a restart, and confirms it worked. If dnscrypt-proxy does not acknowledge, it is restarted instead.
Reapply rulesPuts every firewall rule back now.
Run checksRuns both health checks immediately and shows the raw result.

Firewall

Every rule the module needs, checked live: DNS redirect (IPv4 / IPv6), leak guards, QUIC block, the IPv6 killswitch, and whether the kernel has the xt_owner match the IPv4 leak guard needs. active is good, missing is not — Reapply rules fixes it, and the watchdog does too within seconds. off means switched off by a setting.

System

Module version, SELinux, Android Private DNS (should be off), network, busybox and the blocklist size.

Android's Private DNS uses its own encrypted channel (port 853) and would go around this module and its blocklists. The installer switches it off; if it is on again — Android settings, a restore, another app — a Turn off button appears in that row.

A red or amber dot on the System tab means something there needs attention.

One action at a time: while a button's command runs, the other buttons are dimmed and taps on them are ignored — including taps made while the screen was busy, which Android would otherwise deliver all at once afterwards. Tabs, log filters and Refresh always work.

10 · system — ip mode
modeipv6ipv6 dnsaaaa answers
IPv4 onlyoff—blocked
IPv6 compatibleonthrough the proxyblocked
Dual stackonthrough the proxyanswered
  • IPv4 only (default) — IPv6 switched off in the kernel and the firewall. Strongest leak protection.
  • IPv6 compatible — for carriers that only give IPv6 (464XLAT). On those, "IPv4 only" means no connection at all. Apps keep using IPv4.
  • Dual stack — full IPv6. Websites can see your IPv6 address.

Switching applies immediately — no reboot. Coming out of IPv4 only, the network gets its IPv6 addresses back within seconds, but Android only notices after it reconnects. The module checks this and, only if Android missed it, reconnects Wi-Fi or mobile data by itself for a moment.

Kernel IPv6 NAT

Sending IPv6 DNS into the proxy needs IPv6 NAT in the kernel (CONFIG_IP6_NF_NAT). Without it the IPv6 modes run limited: IPv6 DNS is dropped instead — no leak, but apps must use IPv4 DNS, which an IPv6-only network may not have.

This network

Shows whether the current network has IPv4, IPv6, or is IPv6-only with 464XLAT. If you are on IPv4 only in a network without IPv4, the section tells you to switch.

12 · log

One log for the module (M) and dnscrypt-proxy itself (D). Filter by level (INFO / WARN / ERR) and by source, choose how many lines to show, or clear it.

Many Network change detected lines on mobile data are normal: the modem keeps recreating its connections and dnscrypt-proxy rotates its keys each time.

15 · vpn & companion modules

With a VPN (e.g. WireGuard)

Works alongside. Remove the DNS = line from the WireGuard config, so the tunnel does not try to set its own DNS server — dnscrypt-proxy stays in charge, and its encrypted queries travel inside the tunnel.

this modulevpnboth
DNS lookups hidden from carrieryesyesyes
Sites you visit hidden from carrierno ¹yesyes
Your IP hidden from sitesnoyesyes
Ad & tracker blockingyes—yes
Works when the VPN dropsyes—yes

¹ Encrypted DNS hides the lookup, but the carrier still sees which IP addresses you connect to and, for most sites, the site name in the TLS handshake.

ipset-arm64

A DNS blocker cannot stop an app that connects to a hard-coded IP address — it never asks DNS. The companion module ipset-arm64 blocks by IP address at the firewall instead. The two do not conflict and cover each other's blind spots.

Conflicting modules and apps

The installer looks for other DNS changers (AdAway, systemless hosts, RethinkDNS, NextDNS, Blokada, …) and offers to remove them. Two things fighting over DNS means neither works reliably.

16 · troubleshooting

No internet

  • Look at the banner. Nothing resolves on a public Wi-Fi → it wants a login: Pause, log in, Resume.
  • On mobile data with an IPv6-only carrier → IP mode → IPv6 compatible.
  • Otherwise: System → Restart daemon, then check the Log for red lines.

A site or app does not work

Probably a blocklist. Open the Dashboard right after it fails, tap the red rejected entry in Recent Queries → Allow. Or Tools → Check the domain.

DNS Test shows my carrier

Check the banner is Protected, Private DNS is off (System), and no VPN sets its own DNS. System → Firewall: the redirect rules must be active.

Blocklist update fails

The log box shows which list and why. Already-cached lists keep working. Try another source if one site is down.

Something else

System tab first — every row is a live check. Then the Log with WARN and ERR only.

17 · update & uninstall

Updating the module

Your settings, custom list, allow list, IP lists (allowed-ips.txt, blocked-ips.txt), chosen resolvers and cached blocklists are kept. The old config is backed up with a date in /data/adb/dnscrypt-proxy/.

Uninstall

Remove the module in your root manager and reboot. Every firewall rule is removed, IPv6 and Android Private DNS are restored to how they were, and the module's files are deleted.
